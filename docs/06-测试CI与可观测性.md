# 阶段 6：测试、CI 与可观测性

## 1. 阶段目标

建立持续质量门禁和生产可观测性，使安全、并发、迁移和生命周期问题能够在发布前发现，并在生产故障时快速定位。

本阶段的部分基础工作应在前面阶段提前实施；本文件描述最终目标状态。

## 2. 测试分层

### 2.1 单元测试

范围：

- 配置解析和校验；
- 授权规则；
- 配额计算；
- 状态机；
- URI、端口和资源参数校验；
- Web 响应映射；
- 命令 argv 构造。

要求：

- 不访问真实 `data/`；
- 不运行 Docker、Caddy、iptables 等外部命令；
- 不依赖测试执行顺序；
- 可并行运行；
- 每个测试使用独立临时目录。

### 2.2 组件测试

范围：

- application service + 内存 repository；
- application service + SQLite repository；
- HTTP Handler + fake adapter；
- system lifecycle；
- WebSocket 连接和广播。

重点覆盖：

- 两用户权限矩阵；
- 会话撤销；
- CSRF；
- 并发端口和配额；
- saga 补偿；
- start/stop 幂等。

### 2.3 集成测试

在受控 Linux 环境执行：

- Docker/Podman；
- Caddy validate/reload；
- socat；
- ttyd；
- SmolVM（环境允许时）；
- S3/FUSE（使用专用测试端点或 mock server）。

集成测试使用独立 namespace、端口区间、临时目录和资源标签，结束时检查无残留。

### 2.4 端到端测试

最小关键流程：

1. 管理员创建普通用户；
2. 普通用户登录；
3. 创建资源并访问；
4. 验证另一个用户不能操作；
5. 重启服务并恢复状态；
6. 删除资源和用户；
7. 验证会话失效和资源清理。

## 3. CI 计划

### 3.1 PR 流程

每个 PR 执行：

```text
format-check
clj-kondo
unit-test
component-test
namespace-load
uberjar-build
secret-scan
```

要求：

- 所有工具固定版本；
- warning 是否阻断构建采用明确策略；
- 构建在干净 checkout 中完成；
- 不读取开发者本机配置；
- 不向仓库写入测试产物。

### 3.2 主分支流程

额外执行：

- Linux 外部依赖集成测试；
- 数据迁移测试；
- 依赖漏洞扫描；
- 制品 SHA-256 和 SBOM；
- 容器镜像扫描（若发布镜像）；
- 发布候选 smoke test。

### 3.3 定期流程

- 依赖更新检查；
- 备份恢复演练；
- 长时间运行和资源泄漏测试；
- 端口/配额并发压力测试；
- 凭据和秘密扫描；
- 过期兼容代码清理检查。

## 4. 结构化日志

建议输出 JSON 或稳定 EDN 字段。最少包含：

```clojure
{:timestamp ...
 :level :info
 :event :container/create
 :request-id ...
 :user ...
 :resource-id ...
 :duration-ms ...
 :result :success}
```

外部命令日志增加：

- adapter；
- 可执行文件；
- 脱敏 argv；
- exit code；
- duration；
- timeout/cancel 状态。

禁止记录：

- 密码；
- Bearer token；
- CSRF token；
- S3 secret；
- ttyd 凭据；
- 未脱敏的完整请求 body。

## 5. 指标

建议指标：

### HTTP

- 请求数量、延迟、状态码；
- 当前请求数；
- 认证失败和限流次数；
- 每用户/IP WebSocket 连接数。

### 资源管理

- 容器和 VM 数量；
- 各状态资源数量；
- provisioning/deleting 持续时间；
- saga 失败和补偿失败次数；
- reconciliation 差异数量。

### 基础设施

- 外部命令耗时和失败率；
- Caddy validate/reload 结果；
- 端口池使用率；
- reservation 数量和超时回收数；
- DB 事务延迟和失败率；
- 后台任务最近成功时间。

### JVM

- heap/non-heap；
- GC 次数和暂停；
- 线程数；
- uncaught exception；
- 进程打开文件和子进程数量。

## 6. 审计日志

高风险操作必须记录：

- 登录成功/失败；
- 会话撤销；
- 用户创建、删除、角色和配额修改；
- 资源创建、启动、停止、删除；
- 端口暴露和取消；
- Caddy 规则变更；
- 管理员跨用户操作；
- 数据迁移和 reconciliation 修复。

审计记录至少包含 actor、目标、动作、结果和 request ID，并与普通应用日志区分保留策略。

## 7. 告警

优先告警条件：

- 连续登录失败异常增长；
- provisioning/deleting 长时间未完成；
- 补偿失败；
- Caddy reload 持续失败；
- 数据库不可写或完整性检查失败；
- 端口池接近耗尽；
- reconciliation 发现未知或孤儿资源；
- JVM OOM、线程数或子进程数异常；
- readiness 持续失败。

## 8. 文档

最终至少包含：

- README 和快速开始；
- 配置字段参考；
- 支持平台和外部依赖矩阵；
- JVM 构建与部署；
- systemd 服务说明；
- 数据迁移；
- 备份与恢复；
- 安全首次启动；
- 测试分层和本地命令；
- 常见故障排查；
- 发布与回滚流程。

## 9. 退出标准

- PR 必须通过格式、lint、测试和构建；
- 单元测试不依赖真实外部环境；
- Linux 集成测试可以重复执行且无资源残留；
- 核心安全和并发回归场景被覆盖；
- 生产日志可关联请求、用户和资源；
- 关键失败有指标和告警；
- 部署、备份、恢复和回滚文档经过演练。
