# 阶段 1：安全与数据基线

## 1. 阶段目标

在 JVM 迁移前修复可被直接利用的安全问题，并将源码、配置模板和真实运行数据分离。

本阶段原则上不改变运行时和主要架构，重点是安全止血和建立回归测试。

## 2. 进入条件

- 已备份当前 `data/` 目录；
- 已确认工作区内现有未提交修改的归属；
- 已记录当前管理员、用户、容器、VM、转发和 Caddy 规则；
- 已准备一个非生产测试环境。

## 3. 工作项

### 3.1 统一资源级授权

涉及模块：

- `src/culvert/docker.clj`
- `src/culvert/smolvm/manager.clj`
- `src/culvert/forward.clj`
- `src/culvert/caddy.clj`
- `src/culvert/web/handlers.clj`

任务：

1. 定义统一 actor 结构，例如：

   ```clojure
   {:username "alice"
    :admin? false}
   ```

2. 实现统一的 `authorize-resource!`；
3. 所有按 ID 修改资源的领域函数必须接收 actor；
4. 覆盖 Docker/SmolVM 端口增删、切换、日志停止等遗漏路径；
5. 查询和变更使用相同的所有权语义；
6. 禁止只在 Handler 中做所有权检查。

验收：

- 用户 A 无法查询或修改用户 B 的私有资源；
- 管理员仍能执行明确允许的管理操作；
- 所有拒绝操作在执行外部命令前结束；
- 权限矩阵有自动化测试。

### 3.2 移除 `legacy-user` 隐式共享

任务：

1. 统计所有缺少 owner 或 owner 为 legacy 用户的记录；
2. 制定一次性归属迁移规则；
3. 无法确定归属的记录分配给系统主体，只允许管理员管理；
4. 删除“普通用户可访问 legacy 资源”的特殊分支；
5. 如果需要共享，后续引入显式 `visibility` 或 ACL，不复用用户名。

验收：

- 历史数据迁移前后数量一致；
- 普通用户不再看到管理员或系统遗留资源；
- 迁移脚本可重复执行且不会重复修改正确数据。

### 3.3 关闭日志 ttyd 裸露

任务：

1. 日志 ttyd 默认只监听 loopback；
2. 通过主应用或 Caddy 提供受保护入口；
3. 使用短期、单用途、绑定用户与容器的访问 token；
4. 增加空闲超时和服务端自动清理；
5. 停止日志服务时校验资源所有权；
6. 禁止在日志中输出 ttyd 密码或访问 token。

验收：

- 未认证客户端不能直接访问日志 ttyd；
- 过期 token、错误用户、错误容器均被拒绝；
- 浏览器异常关闭后服务最终会自动回收。

### 3.4 修复会话撤销模型

任务：

1. token 不再长期信任登录时的角色与配额快照；
2. 用户记录增加 `auth-version` 或等价版本字段；
3. token 保存 username/session ID/auth version；
4. 密码修改、角色变化、用户删除时撤销对应会话；
5. 提供“撤销该用户全部会话”管理能力；
6. 记录会话创建、撤销和失败验证的审计事件。

验收：

- 删除用户后旧 token 立即失效；
- 修改密码后旧 token 立即失效；
- 管理员降权后旧 token 不再拥有管理员权限；
- 配额读取来自当前用户状态。

### 3.5 强化密码存储

任务：

1. 优先引入 Argon2id；
2. 如暂时继续 PBKDF2，按目标机器基准调整到约 100–250ms；
3. 移除长期明文密码验证分支；
4. 旧格式成功登录后自动重哈希；
5. 启动时检测弱默认管理员密码并拒绝或显著告警。

验收：

- 新密码不使用 10,000 次 PBKDF2；
- 数据库中不再新增明文密码；
- 旧哈希有明确兼容和迁移测试。

### 3.6 将 CSRF 绑定到会话

任务：

1. CSRF store 保存 session/user/action/expiry；
2. 管理操作至少绑定当前 session；
3. 高风险操作使用一次性 token；
4. 增加 `Origin`/`Referer` 校验作为纵深防御；
5. 容量清理在单次原子更新中完成。

验收：

- 用户 A 的 CSRF token 不能被用户 B 使用；
- token 过期、会话撤销或 action 不匹配时验证失败；
- 高风险 token 成功使用后不能重放。

### 3.7 隔离配置、秘密和运行状态

任务：

1. 仓库只保留脱敏模板；
2. 将真实配置、用户库、资源库和临时文件加入 `.gitignore`；
3. 支持通过环境变量或 CLI 参数指定配置目录和数据目录；
4. 运行数据目录默认位于仓库外；
5. 敏感文件要求 `0600`；
6. 轮换 Git 历史中出现过的管理员和 shell 凭据；
7. 评估是否需要清理 Git 历史。

注意：对已跟踪文件，仅修改 `.gitignore` 不会停止 Git 跟踪，需要单独执行索引迁移。实施时必须先备份数据。

验收：

- 新 clone 不包含真实用户和运行状态；
- 首次启动不会使用 `admin/admin123`；
- 更新源码不会覆盖生产数据；
- 数据目录权限检查有测试或启动诊断。

### 3.8 加固代理输入和限流

任务：

1. Caddy target 使用 URI parser 验证；
2. 拒绝控制字符、空白注入、userinfo 和非法 scheme；
3. 明确是否允许 loopback、私网、link-local 和 metadata 地址；
4. Caddy 配置替换前执行 validate；
5. 只有来自受信代理的请求才解析 `X-Forwarded-For`；
6. 标准化 IP，限制 key 长度；
7. 限流更新改为单次原子状态转换。

验收：

- 伪造转发头不能绕过限流；
- 非法 target 不会进入 Caddy 配置；
- Caddy validate 失败时保留上一份有效配置。

## 4. 测试要求

本阶段至少增加：

- 两用户资源权限矩阵；
- 会话撤销测试；
- CSRF session 绑定和重放测试；
- ttyd 未认证访问测试；
- Caddy target 注入和 SSRF 边界测试；
- 可信代理和伪造 header 测试；
- legacy 数据迁移测试。

## 5. 退出标准

- P0 安全问题全部关闭；
- 不再从 Git 工作树直接读写真实运行状态；
- 安全回归测试通过；
- 数据迁移和凭据轮换已记录；
- 生产切换前可以恢复旧数据备份。

## 6. 回滚策略

- 保留迁移前只读数据备份；
- 所有 schema 修改提供向后兼容读取或逆向迁移；
- 授权模型出现误判时，只允许回滚代码，不恢复已泄漏凭据；
- ttyd 新入口不可用时可临时禁用日志功能，不恢复公网无认证模式。
