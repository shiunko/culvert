# 工作流原语

本阶段提供三个 BB/JVM 兼容、无额外依赖的工作流组件。它们不连接 repository 或 runtime adapter，调用方负责在 application service 中组合。

## 1. 资源状态机

命名空间：`culvert.workflow.state-machine`

状态使用持久化层兼容的字符串：`requested`、`provisioning`、`running`、`stopped`、`deleting`、`deleted`、`error`。输入也可使用同名 keyword，输出统一为字符串。

```clojure
(state-machine/transition {:id "vm-1" :state "requested"} :provisioning)
;; => {:id "vm-1" :state "provisioning"}
```

`transition` 和 `transition-state` 均为纯函数。未知状态抛出 `::state-machine/invalid-state`，非法转换抛出 `::state-machine/invalid-transition`；`ex-data` 包含源状态、目标状态及允许的目标集合。`deleted` 是终态，重复转换也不作为合法状态事件。

## 2. 同步 saga

命名空间：`culvert.workflow.saga`

每一步为 `{:id id :do! zero-arg-fn :undo! zero-arg-fn}`。`execute` 顺序执行 `do!`；失败后仅补偿已经成功的步骤，严格逆序调用其 `undo!`。一次补偿失败不会阻止其余补偿。

- `execute` 总是返回结构化执行结果；业务步骤失败时结果的 `:status` 为 `:failed`；
- `execute!` 成功时返回相同结果，失败时抛出 `ex-info`；
- 失败数据包含 `:failed-step`、`:completed`、`:compensation-errors`，原始执行异常是 `execute!` 异常的 cause；
- `:compensation-errors` 中保留每个失败补偿的步骤 ID 与原始异常。

## 3. Reconciliation 报告

命名空间：`culvert.workflow.reconciliation`

```clojure
(reconciliation/report desired actual)
```

输入可为以资源 ID 为 key 的 map，或包含 `:id` 的资源序列。输出固定包含：

- `:create`：desired 中存在、actual 中缺失；
- `:update`：共有资源的 desired 字段与 actual 不同；
- `:in-sync`：desired 字段均一致；actual 的额外观测字段不形成差异；
- `:unknown`：只存在于 actual，默认 `:action :retain`；
- `:delete`：默认永远为空。

报告按 ID 的可打印形式稳定排序，函数无副作用，相同快照重复执行得到相同结果。只有显式传入 `{:delete-unknown? true}` 才会把未知资源列为删除候选；这仍然只是报告，不执行删除。
